数字 IC 后端设计里，"Floorplanning（布局规划）"经常被一句话带过——"就是给标准单元摆个地方放宏单元"。但实际上，它是整个物理设计的**第一块画布**：芯片的面积、功耗、时序收敛难度、布线拥塞，甚至封装引脚分配，几乎都在这一步定了七八成。本文从设计流程定位、核心对象、优化目标、常见方法到工程教训，把 Floorplanning 讲透。

## 一、它处在流程里的哪个位置

一个典型的数字 ASIC 设计流程是这样走的：

```
RTL 设计 → 综合(Synthesis) → 形式验证(Formal) → 布局规划(Floorplan)
        → 标准单元放置(Placement) → 时钟树综合(CTS) → 布线(Routing)
        → 时序签核(Signoff STA) → DRV/LVS → GDS 递交
```

Floorplan 夹在综合和放置之间。它的输入有三样：

- **门级网表（Gate-level netlist）**：综合后的单元清单和连接关系。
- **约束（Constraints）**：时钟定义（SDC）、I/O 时序、面积与功耗目标。
- **工艺数据**：标准单元库、IO 单元库、宏单元（memory/analog IP）的尺寸与端口位置。

而它的输出，是一张"硬性地图"：

1. **芯片外形（Die outline）**：长宽、纵横比（aspect ratio）、利用面积。
2. **硬宏的位置**：每颗 memory、IP、模拟模块放在哪、朝向哪。
3. **IO、电源地 pad 的排布**：引脚怎么分布、电源网络（power grid）主干怎么走。
4. **电源域与时钟域的划分**：多电压域的边界、时钟源（CTS 后的 PLL/时钟门）位置。
5. **标准单元区域**：留出的"可放单元的地盘"，要么一片簇放，要么切开。

一句话总结：**Floorplanning 回答"哪些大块放哪里、剩下多大地方塞小单元"这两个问题。**

## 二、要处理的对象：硬宏、软模块、IO 与网络

### 2.1 硬宏（Hard Macro）

Memory（SRAM、寄存器堆）、模拟 IP、PLL、SerDes 这类 IP 是**硬宏**：布局工具无法改变它们的形状和内部 pin 位置，只能整体搬运、旋转、翻转。它们通常占满 50%~70% 的重头戏：

- **尺寸已知**：LEF/DEF 里有精确的宽高和端口坐标。
- **pin 分布决定绕线走向**：SRAM 的位线很敏感，通常要求指定位置、指定方向逼出去；模拟模块更挑剔，常常要求周围"留静区"（keep-out），禁止数字单元和长走线靠近。

### 2.2 软宏与模块（Soft/Module）

还没有被综合打散的 RTL 模块叫软宏，可塑性高，但**撕碎后引脚会乱**。工程上常对给定模块先局部做一次综合，估出它的尺寸（面积、所需行数），再决定要不要"团聚放置"（保持模块边界完整），以减少跨模块走线。

### 2.3 IO 和 Pad

IO 单元（input/output pad）决定引脚顺序。经典做法是**IO 引脚顺序在 RTL 阶段就应该和封装绑定**——封装 ball map 出来照着排。排错的代价是绕线绕一大圈甚至改版。实践中最重要的原则：

- **高速信号、敏感模拟信号尽量短、尽量直**，靠近对应功能块。
- **电源/地 pad 均匀分布**，别把几十个 GND 挤在一角（压降会崩）。
- **时钟/复位这种全局信号**，pad 位置尽量对称居中，减轻 CTS 负担。

### 2.4 网络对象：电源、时钟、关键路径

Floorplan 阶段就要"抽象地"想清楚三类网络：

| 网络类型 | 为什么此时就要想 | Floorplan 层面的动作 |
|----------|------------------|----------------------|
| **电源/地** | 电流路径决定压降(IR drop)和电迁移(EM) | 沿芯片四周做电源环(power ring)、纵向电源条(stripes)、确定宏的 power pin 朝向 |
| **时钟** | 长时钟走线导致偏斜(skew)大、功耗高 | 时钟树根(源)尽量居中；高扇出时钟门靠近源 |
| **数据/关键路径** | 关键路径长度直接决定能否收敛 | 让关键路径两端"物理相邻"，优先短连接 |

## 三、Floorplan 的量化目标

不要以为"摆个位置"没有优劣之分。衡量一个 floorplan 好坏，常用的指标有：

### 3.1 线长（Wirelength）

总布线长度，常用 **HPWL（half-perimeter wirelength）**——一组连线端点的包围盒半周长之和——做快速估计。线长直接关联：面积（布线通道）、功耗（电容）、时序（RC 延迟）、DRC 违例数。**线长是百分百的大目标。**

### 3.2 面积利用率（Utilization）

$utilization = \frac{\sum 单元面积}{标准单元可用区域面积}$。利用率太高（>90%）→ 没有布线通道，拥塞爆表；太低 → 浪费 die。经验上数字逻辑 60%~80% 较稳妥，纯模拟或混合信号会更低。

### 3.3 布线拥塞（Congestion）

布线时需要"横跨越过"宏或把宏切开的口子，是最容易产生拥塞的地方。拥塞评估器把芯片切成网格，估每个 bin 需要的线道（track）与可用的比：

```
congestion ratio = 需求 track / 可用 track
ratio > 1.05~1.1  → 布线基本不可能，回炉改 floorplan
```

### 3.4 时序可达性（Timing Feasibility）

关键路径两端的物理距离要满足延迟预算。估算公式大致是 $delay \approx R_{sheet} \cdot C_{unit} \cdot L^2$，距离翻倍、延迟约翻两倍——所以"把关键路径放近"不是玄学，是数学。

### 3.5 功耗与电压降

高功耗宏（CPU 核、大 SRAM 阵列）附近压降最狠。仿真的结果往往要求在 floorplan 阶段就预留大功率环和密集 stripe，失之毫厘，签核差之千里。

## 四、怎么求这个"放置问题的近似解"

Floorplanning 本质上是一个**组合优化问题**：把 N 个矩形块以不重叠的方式摆放，最小化线长/面积/拥塞的加权和。它是 NP-hard 的，工程上用启发式 + 模拟退火（SA）为主流。

### 4.1 经典方法演进

| 方法 | 思路 | 特点 |
|------|------|------|
| **切分法（Partitioning）** | 用 min-cut（如 FM 算法）把网表切进芯片区域，递归四等分 | 快、保证连通性；早期主流 |
| **切片结构（Slicing）** | 用波兰表达式（Polish expression）表示反复"横向/纵向切"的解剖树 | 能量化面积/线长，天然支持 SA |
| **非切片（Non-slicing，如 B\*-tree）** | 用二叉树表示 v 型（B\*-tree）布局 | 表达力更强，可覆盖不能切片的情况，现代主流 SA 基于它 |
| **解析法（Analytical）+ 全局布局** | 连续化目标函数（线长-平滑化）+ 密度惩罚项迭代求解 | 单元数量大时的必选项，宏和单元同框架优化 |
| **机器学习/学习式** | 用 GNN 嵌入网表结构预测布局 | 学术界热门、工业界还在证明自己 |

### 4.2 实际工具里的流程

现代 EDA（Innovus、ICC2 等）的 floorplan 命令通常走这样的循环：

```
1. 读入 netlist + floorplan 约束（object 的 group、位置 hint、Keep-out）
2. 初始布几个宏（手动摆或工具自动）
3. 预览评估（Total wirelength、congestion、utilization 报告）
4. 有硬需求的地方手动指定（memory 固定、模拟保护区）
5. 让工具做 macro placement / 全局放置
6. 反复看报告、迭代，直到稳定
```

**经验法则：宏自己摆，工具来验证。** 一颗芯片的工作量很多时候花在"知道哪些宏必须挨着放、哪些必须分开"这种领域知识上，而不是纯让算法盲跑。

## 五、几类特别场景的实战要点

### 5.1 混合信号（Mixed-Signal）

模拟数字混在同一颗 die 上，最重要是**隔**：

- 数字宏尽量集中成"数字岛"，与模拟区用 guard ring 或空旷沟槽隔开。
- 模拟敏感信号（ADC 输入、PLL VCO）走线要短、要避免与数字总线并行。
- 各自电源分开（模拟 VDD 与数字 DVDD 独立环、独立焊盘），避免数字开关噪声串扰。
- 噪声最猛的模块（时钟发生器、开关电源）放最边缘、远离敏感输入。

### 5.2 多电压域（Multi-voltage / Power Gating）

- 每个电压域的供电区要么整块（domain 边界对齐 power strip），要么用 power switch 隔开。
- 不同域间的电平转换单元（level shifter）要放在边界两侧、尽量贴边，减少跨域长线。
- **电源门的摆放密度**直接决定压降，floorplan 时必须预留 switch 的列，否则后面硬挤必炸 IR。

### 5.3 大 SoC / 层次化（Hierarchical）

- **物理分区（physical partition）**：把 SoC 切成子块，各自独立做 floorplan+放置+CTS+布线，最后顶层层级拼合（block-level 复用）。微处理器就常这样。
- 分区边界要选"连线最少"的切口（min-cut），并且为跨块 net 预留边界 pin/buffer。
- 顶层只有 IP 之间的"藕断丝连"网络，纯摆位即可，工作量小很多。

### 5.4 功率/散热

高功率芯片（GPU、数据中心 SoC）在 floorplan 阶段就要回答"热点在哪"：

- 高功耗聚cluster会形成热斑（hotspot），物理上局部温度更高、迁移泄漏更多。
- 方案常是**把热源错开分布**，或在热源附近放宽密度、增加散热路径（TSV、碳基散热片）。
- IR 仿真（voltage drop）必须在宏密集区看 drop map，那些"红区"要预留额外供电条。

### 5.5 Pitch Matching：宏边界上的"齿距对齐"

Pitch（间距）是物理设计里最常被忽略、却最能决定"这层能不能布下去"的量。**Pitch Matching 指的是让宏单元的引脚间距、与标准单元行的行距/布线轨道（track）间距对齐**，让信号能以最少拐角直接逼出：

```
标准单元行(行距 = 1x)  ──┬──┬──┬──┬──┬──┬──  row
                          │  │  │  │  │  │
宏引脚(间距 = 1x, 对齐)   ●  ●  ●  ●  ●  ●   → 直出，零 jog，最短
宏引脚(间距 = 0.7x, 错)   ●● ●● ●●          → 每根线都得折，通道被 jog 堵死
```

三处最常见的对齐点：

- **标准单元行与宏 pin 极点对齐**：宏（尤其 SRAM）引脚通常按固定 pitch 排布；把它的朝向一转、offset 一调，让引脚正好落在标准单元行能"零折线直出"的位置。错位 0.25 个 pitch，拥塞就可能上一档。
- **行距与 track pitch 的比例**：布线层 track pitch 是工艺定死的（如 0.080/0.040 µm 线/间距），宏与单元区是否按整数倍对齐，直接决定过宏连接要不要牺牲一层通道。
- **模拟/mixed-signal 里的"Pitch Matching"另一个含义**：把需要匹配的晶体管与走线做成**完全同构、同朝向、同间距**排布，让工艺梯度（氧化层厚度梯度、聚晶掺杂梯度、温度梯度）对两者施加相同影响——这是 ADC/DAC、电流镜、差分对达到匹配精度（如 10-bit 以上）的物理前提。数字区关注"能不能走通"，模拟区关注"差分对要不要隔着分布梯度"。

工程上的落地手段：旋转/翻转宏使引脚朝向单元区；手动或工具约束 pin alignment/offset；对模拟模块用明确的"配对/对称"约束（symmetry constraint）让工具照做。一句口诀：**"能对齐的 pitch 一定对齐，对齐不了就给它留一条直通道。"**

### 5.6 Slice Plan：把重复结构切成一排"薄片"

Slice Plan 是把芯片或模块区域**切成一条条竖（或横）的、宽度一致的狭长矩形（slice）**，每条放同一族重复电路，整体排成一个规则的阵列。它属于"规则化/模板化"布局，和随机放置完全是两种思维。

典型应用场景：

| 对象 | 一个 slice 是什么 | 为什么用 slice plan |
|------|------------------|---------------------|
| **SRAM / 寄存器堆阵列** | 一个 wordline 列 / 一条 bank | 位单元、灵敏放大器完全同构，复制即得 |
| **SerDes 收发器** | 一个 lane（通道） | lane 之间天然重复，宽度就是 lane pitch |
| **多通道 ADC/DAC** | 一个转换通道 | 通道一致性要求彼此同构，slice 保证 |
| **栅阵列 / FPGA 基础结构** | 一个 CLB/CLE 列 | 规则 fabric 从器件层就如此 |
| **标准单元行本身** | 一行 row 就是一个 slice | "行=slice"是所有数字布线的底子 |

Slice Plan 的价值：

- **复用**：一个 slice 设计好，复制 N 次即可，接口、电源、时钟全自动跟着走。
- **一致性**：同名器件位置同构 → 电学特性一致，差分对/通道间匹配天然满足（正好呼应 5.5 的模拟 pitch matching）。
- **可布性可预测**：电源/时钟沿 slice 纵向均匀走，横向只需处理 slice 之间的接口线，拥塞评估一眼可见。
- **工具友好**：整排 slice 用一条放置命令/一个循环就能排完，还能整体平移、整体翻转。

要注意的坑：

1. **slice 的宽度/间距必须和 pitch 体系咬合**（回到 5.5）——slice 宽不是任意值，得落在 track 整数倍上。
2. **slice 边界要留走线通道**：接口线都挤在 slice 交界处，不留 track 就是人为制造拥塞。
3. **slice 间对称性要显式声明**：需要匹配的 slice 用 symmetry 约束锁死，别让工具把其中一片翻转了事。
4. 区分两个概念：**slice plan（工程上的模板复制阵列）** 和算法里的 **slicing floorplan（用横竖切分树表达布局的数学模型）**——一个讲"怎么摆重复块"，一个讲"怎么描述一张任意布局"，别混。

## 六、常见翻车场景（血泪清单）

1. **memory 朝向错了 90 度** → 位线逼向错误方向，绕线绕出 2x 长度，时序救不回，只能改版。
2. **IO 排列跟着网表默认走** → 封装 ball map 对不上，绕线通道被 IO 长线堵死。
3. **利用率压到 92%** → 布线拥塞一堆红块，DRC 修不动，最后拆东墙补西墙。
4. **时钟树源放墙角** → 全片 clock skew 爆表，CTS buffer 海堆，功耗白送。
5. **模拟区没留 Keep-out** → 数字 buffer 怼到模拟周围，SAR 转换精度掉比特，靠测试打回才知道。
6. **电源环初期没设计宽** → IR drop 在签核时才亮红灯，此时加 stripe 已经要动 macro 排布。
7. **宏引脚 pitch 没和行距对齐** → 连接线被迫层层折返，拥塞和额外长度双爆，DRC 最后只能用 M2 换 M3 硬挤。
8. **slice 宽随手填了个非整数倍数值** → 整排 slice 上不了 track，布线前就得推回去重切，白做一轮。

几乎每一条都可以归结为：**"这一步图省事，后面花十倍的伤。"**

## 七、流程化建议

给后来者一套可实操的开工姿势：

1. **先要三样东西再动手**：确认过的 netlist、完整约束、IO/封装 ball map。
2. **自己先列一个"意向图"**：哪几颗宏必须挨着（靠数据流）、哪几颗必须远（敏感 vs 吵闹）、IO 优先级排序。工具看到的只是网表，领域顺序你决定。
3. **小步快跑**：先粗排一版看 util/wirelength/congestion 三张报表，再逐步收紧约束，任何一步爆红都停下来回炉，别攒到后面。
4. **用报告往回推**：congestion map 红的地方要么是宏切错方向，要么是 track 不够；改动的对象永远优先是宏取向和位置，其次才是 density。

## 结语

Floorplanning 在流程图里只占一个格子，但它决定了下游所有环节的天花板。它是最不"自动化"的一步——需要工程师懂网表、懂封装、懂功耗、懂信号完整性，然后用 EDA 的评估报告来验证自己的直觉。而那些看似琐碎的"对齐"功课——宏引脚的 pitch 对齐、重复结构的 slice 规划——恰恰是把"能看"变成"能布得通"的关键。老后端常说的一句话很在理：**"Placement 用算法，能不能收敛靠佛；Floorplan 用脑子，后面顺不顺看你。"** 把这第一张画布画好了，后面的一半工作其实是水到渠成。
