人形机器人的本质是一台"带腿的实时控制系统"：几十个关节、上百个自由度，每个关节背后都有执行电机、位置/力矩传感器和伺服驱动，它们必须以严格确定性的节拍配合，否则机器人都站不稳。把这些零部件拧成一个整体、又保证延迟和同步的，正是**关节与主控之间的通信总线和协议栈**。

这篇文章把人形机器人内部通信这件事拆开讲清楚：主流总线协议、典型拓扑、传感器侧接口、执行器侧方案、行业实例，以及正在进行的标准化和演进趋势。

## 一、先给出结论：当前行业的分层通信架构

IEEE 802.1 在 2025 年的一份内部报告中给了业界通用的机器人内部通信画像：

```
┌──────────────────────────────────────────────────────────────┐
│        三个并行骨干 + 若干专用通道                            │
│                                                              │
│  EtherCAT ──────→ 驱动控制（关节伺服，实时闭环）              │
│  千兆以太网 ─────→ 感知骨干（相机、LiDAR、点云）              │
│  GMSL / MIPI ────→ 摄像头链路（原始图像直连算力板）           │
│  CAN / CAN-FD ───→ 低速外设（灵巧手、状态类传感器）           │
│  I2C / SPI ───────→ 板级传感器（IMU、温度、磁编）             │
└──────────────────────────────────────────────────────────────┘
```

一句话概括：**EtherCAT 管"动"（驱动控制），千兆以太网管"看"（感知），CAN/复杂外设管"杂"（低速设备），板内 I2C/SPI 管"小"（芯片级传感器）。**

这套架构不是一天形成的，它从工业机器人、协作机器人和四足机器人的路径演进而来，核心诉求始终是三个字——**快（低延迟）、准（高同步）、稳（抗干扰）**。

## 二、四大主干总线逐一拆解

### 2.1 EtherCAT：驱动控制的事实标准

EtherCAT（Ethernet for Control Automation Technology）是 Beckhoff 于 2003 年提出的实时工业以太网协议，后来成为 IEC 61158 标准。它几乎是今天人形机器人**关节驱动侧的默认选择**，原因是它同时拿下了实时性、扩展性、拓扑灵活性和生态成熟度：

- **"飞读飞写"（on-the-fly processing）**：EtherCAT 主站发出的报文在从站间"边传边改"，帧内每个从站处理自己那一段还顺带塞回数据。总线上挂几十个关节，往返也只算一次网络延迟。
- **分布式时钟（Distributed Clocks, DC）**：所有从站可被同步到纳秒级（<50 µs 甚至上百纳秒），这是多关节协调控制的命门。
- **菊花链拓扑**：一个关节接着一个关节串下去，线缆和连接器大幅减少，正好适配人形机器人局促的机械空间。
- **控制频率**：工程上普遍跑 1~4 kHz 的总线周期；TOCABI 团队实测，跳过同步误差后**总线周期可以超过 4 kHz**。

代表性使用案例：

| 机器人 | 关节数 | 驱动方案 | 通信细节 |
|--------|--------|----------|----------|
| TOCABI | 33 DOF | Elmo Gold Solo Whistle | 双通道 EtherCAT 冗余，4 kHz 周期，闭环总延迟约 644 µs |
| LOLA | 低层运动控制 | PI 控制器（EtherCAT） | 2 kHz 校验周期下总线周期实测可再上探 |
| 智元 AgiBot | 一体化关节模组 | EtherCAT + CAN 双协议 | 硬件设计已开源（agibot_x1_hardware） |

### 2.2 CAN / CAN-FD：低速外设的主力

CAN 总线可能比大部分读者的年龄都大（Bosch 1986 年发明），但它至今位于机器人通信分级中的"性价比担当"。

- 传统 CAN 为 1 Mbit/s，**CAN-FD 把数据段提到最高 8 Mbit/s**，单帧最多 64 字节；
- 差分信号天生抗工业现场干扰，线缆便宜、布线随意，不需要像 EtherCAT 那样讲究菊花链顺序编码；
- 代价是带宽和同步精度都低于 EtherCAT，因此定位非常明确：**灵巧手、状态监测、电源管理、低帧率传感器、调试诊断**。

TI 的官方文档（Motor Control in Humanoid Robots, SLLA659）明确指出：人形系统的通信接口"要么是 CAN-FD，要么是以太网（含 EtherCAT），视系统需求而定"。

### 2.3 千兆以太网 / TSN：感知骨干与未来演进

相机、LiDAR、触觉电子皮肤产生的数据量远非 EtherCAT 或 CAN 能承载，因此感知侧走的是普通或工业以太网：

- **高带宽**：单链路 1~10 Gbps，可同时灌入多路深度相机和激光雷达点云；
- **与 DDS/ROS 2 天然契合**：机器人中间件生态直接跑在 IP 网络上；
- **TSN（时间敏感网络）加持下潜力巨大**：802.1AS 时间同步 + 确定性调度，能提供"每包最终到达时间可预测"的通道。业界一直在讨论 TSN 接棒 EtherCAT 的可能性——统一机内通信、降低线缆和芯片种类。其待补短板依然是：成本和 E2E 延迟是否追得上 EtherCAT。

### 2.4 GMSL / MIPI：摄像头专用通道

- **MIPI CSI-2**：摄像头传感器直连 SoC 的经典接口，延迟低、无需压缩，但传输距离短，通常只用在头部/躯干内。
- **GMSL（Gigabit Multimedia Serial Link, ADI 系）**：把 MIPI 信号搬到同轴线缆上做长距离传输，抗干扰强、单线可同时传视频和双向控制通道，特别适合"眼睛"装在头部、算力板装在躯干的布局。

## 三、传感器侧：测量什么、走什么口

把整个人形机器人做一次"传感器普查"，通信负载并非均等，绝大多数数据其实是"小、慢、多"。参考 IEEE 802.1 对双足人形机器人的统计：

| 传感器 | 典型数量 | 采样率 | 单点数据量 | 总线归属 |
|--------|----------|--------|------------|----------|
| 关节编码器 | 24~30 | 500 Hz ~ 1 kHz | ~12 kB/s/关节 | EtherCAT / CAN-FD |
| IMU（姿态/平衡） | 1~2 | 200 Hz ~ 1 kHz | kB/s 级 | SPI → 汇聚上以太网 |
| 足底力传感器 | 8~12 | 200 ~ 500 Hz | 16 bit × 500 Hz ≈ 1 kB/s | CAN / 以太网 |
| 触觉/电子皮肤 | 100~300 taxels | 100 ~ 200 Hz | 单臂约 40 kB/s | 以太网汇聚 |
| 麦克风阵列 | 4~8 路 | — | 约 0.5~2 Mbps | USB / 以太网 |
| 相机（深度+RGB） | 6~10 | 30~90 fps | 数百 Mbps | GMSL/MIPI → 以太网 |

几个值得注意的规律：

1. **编码器走"大动脉"**：关节位置反馈是运动控制闭环的输入，天然挂在与驱动同一条总线（EtherCAT）上，保证"读数"和"下发"同一时钟。
2. **力传感分层**：足底压力参与 ZMP（零力矩点）平衡计算，必须低延迟，所以走 CAN 或直接以太网；而灵巧手内部密度极高的触点传感器常由指尖 MCU 聚合后再上行。
3. **板级传感器走芯片接口**：IMU 的 SPI + 中断引脚、温度/磁编的 I2C，属于"MCU 到传感器"私有短距通信，不参与总线选型。

### 编码器接口的细节

关节处的位置反馈又分两级：

- **电机编码器**（电机轴上，测转子角度，用于 FOC/电流环）：绝对编码器或增量编码器，走 SPI（如 AMS AS5 系列）、BiSS-C、或直接并入驱动 MCU 的增量接口（QEP）；
- **关节编码器**（减速器输出端，测输出角度，用于位置环/力控）：绝对编码器（分辨率 19~23 bit，如多圈磁编或光学绝对值编码器），可选的输出角度反馈一路并入伺服驱动，实现"轴角反馈"闭环。

两级编码器的数据最终都汇聚进驱动 MCU，由驱动 MCU 按控制周期组帧，经 EtherCAT/CAN 上报主控——**主控从不在底层"读原始编码器"，它读的是驱动板整理好的状态向量**。

## 四、驱动侧：从力矩指令到电流闭环

通信总线只管"传指令"，真正干活的在关节驱动板上。一个现代一体化关节模组（宇树、天工、智元等厂商的方案内核）大致长这样：

```
主控(EtherCAT 主站)
   │ 位置/力矩目标 + 模式切换
   ▼
关节驱动 MCU（如 TI AM2612、STM32、Ingenic 等）
   ├─ FOC 电流环：PWM 8~32 kHz，电流环 8~64 kHz
   ├─ 位置环：读两级编码器（SPI/BiSS/QEP）
   ├─ 力/力矩环：读力矩传感器（应变片桥 → Σ-Δ/24bit ADC）
   └─ EtherCAT/CAN-FD 从站 MAC，上报状态向量
   │
   ▼
无框力矩电机 / 外转子电机 + 谐波/行星减速器
```

### 控制层的分解

| 控制层 | 频率典型值 | 所在位置 | 数据流 |
|--------|-----------|----------|--------|
| 电流环（FOC） | 8~64 kHz | 驱动板本地 | 相电流采样 → PWM 占空比 |
| 速度/位置环 | 1~4 kHz | 驱动板本地或主控 | 编码器/轴角 → 力矩指令 |
| 全身协调（WBC） | 500 Hz~1 kHz | 主控/算力板 | 全身运动学 → 各关节目标 |

也就是说总线上的"控制频率"其实是**位置/力矩环的频率**，电流环这种更快的环根本不上总线，全部在驱动板本地闭环。这就是为什么 EtherCAT 跑 1~4 kHz 已足够：每个周期传的是"目标值+状态"，而不是"逐 PWM 占空比"。

### 主控侧的典型硬件

学术界和工业界的落地案例高度一致——主控是一台插了实时网卡的高性能板卡：

- TOCABI：Intel Core i7-10700 主机 + 四口 Intel I340 网卡，SOEM + Xenomai 跑 EtherCAT 主站；
- 工业级：TI AM2612 等实时 MCU 可做硬实时 EtherCAT/TSN 主站，延迟 <2 µs，并拿到 IEC 61508 SIL 3 功能安全认证；
- 商用整机：主控往往用 NVIDIA Jetson Orin 级算力板跑感知 + 运动规划，另配实时核心跑 EtherCAT 主站，中间用共享内存/DDS 衔接。

## 五、拓扑与布线：被忽视的工程决策

通信协议选型之外，"怎么连"同样决定成败。人形机器人内部空间极其吝啬，线缆的**重量、数量、走线路径**都被当作设计变量。

### 菊花链

```
主控 ─┬─ 左腿1 ─ 左腿2 ─ … ─ 左腿N
      └─ 右腿1 ─ 右腿2 ─ … ─ 右腿N
```

- EtherCAT 的典型形态，线缆从躯干沿腿部一路串下去，一个关节断线可能导致后续所有关节失联（可用双通道/环路冗余缓解）；
- TI 明确建议：尽量减少线缆、按关节链分组布线，一般"一条链一个以太网 PHY 段"。

### 环形/冗余

- EtherCAT 支持环路冗余，TOCABI 就用**双通道 EtherCAT** 做了容错——主通道故障时从通道接管，对浮底座机器人这种"摔倒即事故"的场景意义很大。

### 线性总线（多支路）

```
主控 ─┬→ 驱动1 ─┬ → 驱动2 ─┬ → 自然多支
```

- CAN/CAN-FD 天然支持链式挂载，多个低速外设（灵巧手、传感器板）并联在一条总线上，各自用标识符寻址。

工程经验：**按功能域分组（头、左臂、右臂、左腿、右腿、灵巧手）各给一条链**，既是物理布线的自然分区，也是故障隔离的边界。

## 六、行业实例：几张典型的"总线地图"

### 1. 智元 AgiBot（开源硬件可考证）

智元 X1 的硬件设计在 GitHub 开源，其通信画像正是"三骨干"架构的代表：关节驱动走 EtherCAT/CAN 双协议，相机走 MIPI/GMSL 到骁龙/算力板，传感器数据经以太网汇聚。这也是产业调研里"Huawei/Intel whitepaper 统计口径"下的最主流形态。

### 2. 天工（国家地方共建具身智能机器人创新中心）

天工 2.0/3.0 强调"关节导热技术与一体化模组"，其关节模组把无框力矩电机、减速器、驱动、编码器、力矩传感器集成一体，通信上遵循人形机器人一体化关节接口标准的研讨方向——机械参数、接线、电源、通信协议四件套一起标准化。

### 3. 特斯拉 Optimus（侧面印证）

Optimus 大量使用一体化执行器 + 环抱式线缆，公开拆解（按汽车供应链的逻辑）显示其底层信号走标准的车载级 CAN/以太网混合架构，并在关节中就近集成控制器。特斯拉在机器人上的哲学与自动驾驶惊人一致：**供应链复用 + 分布式就近计算 + 冗余安全**。

## 七、标准化：正在发生的"接口统一"

人形机器人当前最痛的是**零部件不互通**：每家整机厂的关节模组接口私有，换一家供应商等于重做定制。2025 年以来中国的标准化动作密集：

- **2025-02**：国家地方共建具身智能机器人创新中心召开"人形机器人电驱动一体化关节接口标准研讨会"，聚焦机械参数、接线方式、电源连接器、通信协议四个方面；
- **2025-12**：工信部成立人形机器人与具身智能标准化技术委员会；
- **2026-02-28**：发布我国首个《人形机器人与具身智能标准体系（2026版）》，覆盖基础共性、类脑与智算、肢体与部组件、整机与系统、应用、安全伦理六大板块，其中**肢体与部组件**明确涵盖执行、感知、通信单元模组的接口规范。

对总线的直接含义：**关节模组的通信协议将逐步收敛**，整机厂不再需要为每家供应商单独写 EtherCAT/CAN 映射；主控和模组之间有望变成"插上即可识别"（类似工业的 ESI 描述文件）的即插即用关系。

## 八、趋势：TSN 会取代 EtherCAT 吗？

这是目前产业和学术争论最热的问题。

**看好 TSN 的理由**：
- 单一以太网统一"动"与"看"，大幅简化线缆和 PHY 类型；
- 带宽从 Gbps 起步，天花板远比 EtherCAT 高，给未来"机载 AI + 高帧率触觉"留下余量；
- 与 DDS/ROS 2 协议栈同源，软开发生态顺滑。

**TNS 要补的课**：
- 延迟与 jitter 要做到"隔了十几个从站仍然亚毫秒"，端到端成本要降到 EtherCAT 的量级；
- EtherCAT 在工业上积累的近 20 年从站芯片生态、功能安全认证（比如 TI AM2 系列直接片上硬核）不易平替。

业界判断：**未来 3 年内，人形机器人的运动控制侧大概率仍是 EtherCAT 主导、CAN-FD 兜底，TSN 先从感知骨干做起，逐步上探到控制侧。** 换句话说，"动"与"看"暂时还不会合流。

## 九、总结

- 通信整体是**分级**的：EtherCAT 管关节驱动（1~4 kHz 实时闭环），千兆以太网管感知，CAN-FD 管低速外设，GMSL/MIPI 管摄像头，I2C/SPI 管板内小传感器；
- 关节驱动是**分布式就近计算**：电流环在驱动板本地闭环，总线上只跑"目标值↔状态向量"；
- 传感器侧核心是**机械分级**：电机编码器走 SPI/BiSS，关节绝对编码器与力矩传感器汇聚进驱动板，再由 EtherCAT/CAN 统一上报；
- 拓扑上**菊花链 + 按肢体分组 + 冗余**是主流工程选择；
- 标准化正在把关节接口（含通信协议）推向统一，TSN 是值得盯住的长期趋势。

给做整机或关节模组的工程师一句话建议：**先把"控制环不上总线"这件事做扎实（电流环全本地），再把总线当作纯指令通道来选型和定速（EtherCAT 1~4 kHz 或 CAN-FD），最后才谈拓扑和冗余——顺序反了，机器人的脚就软。**
