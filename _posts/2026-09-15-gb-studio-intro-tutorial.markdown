写过单片机、FPGA，也该玩玩 1990 年代的"最硬核掌机"了。Game Boy 只有 4.19 MHz 的 8 位 CPU、8 KB RAM、160×144 分辨率的屏幕，但这恰恰让它成为学习游戏开发的一等一平台——约束足够少，反馈足够快。而 **GB Studio** 就是给这块硬件准备的"可视化开发工具"：不用懂 C、不用懂 GBDK，纯拖拽放场景、连事件就能做出一整部能烧录到真卡带上的游戏。本文介绍 GB Studio 是什么、核心概念怎么用，再带一个完整的迷你示例从零跑通。

## 一、GB Studio 是什么

GB Studio 是开发者 **Chris Maltby** 推出的免费开源工具，2019 年发布，目前最新版本是 **4.3.x（2026 年更新）**。它面向任天堂 Game Boy / Game Boy Color，定位类似 RPG Maker：

- **图形化编辑**：场景（Scenes）、角色（Actors）、触发器（Triggers）、事件（Events）全部可视化管理，无需手写代码。
- **内置素材工作流**：精灵图、背景、字形、音乐都有配套编辑器，只要会画 8bit 像素图就能用。
- **自动编译**：底层用 GBDK-2020 和 GBVM 把项目编译成真正的 `.gb` / `.gbc` ROM，可以直接在模拟器里跑，也能烧进 EverDrive 这类闪存卡上真机运行。
- **多平台导出**：除了 ROM，还能导出 Web 版（浏览器里用模拟器玩）以及用于在 itch.io 等平台发布。

关于名字的一点澄清：这里说的是带空格的 "GB Studio"（Game Boy 开发工具），别和某日本同名乐队弄混。

### 为什么选它做入门

对工程师来说，它最大的价值是**把"硬件限制"变成了教学资源**：

| 限制 | 数值 | 对你意味着 |
|------|------|-----------|
| 屏幕 | 160×144 像素 | 一个场景就是一小块画布，设计得明明白白 |
| 同屏精灵 | 最多 40 个，单行 10 个 | 逼你学会"少即是多"的舞台布局 |
| 颜色 | DMG 4 灰阶 / GBC 调色板 | 美术成本极低，草草图就能动起来 |
| 音源 | 4 通道方波/噪声 | 有内置音乐编辑器，节奏、BGM 一条龙 |

约束即风格，这正是复古游戏开发的乐趣所在。

## 二、核心概念：场景、演员、触发器、事件

GB Studio 的整套世界观可以用一句话概括：**场景是舞台，演员站台上，触发器划区域，事件写剧本**。

### 2.1 场景（Scene）

一个**场景**是游戏里的一块地图。可以是关卡、菜单、标题画面、过场 CG。游戏基本上就是很多场景用"切换场景"事件串起来。每个场景都有自己的：

- **背景（Background）**：一张 PNG 像素图，决定"长什么样"。
- **碰撞（Collision）**：在背景上刷出的红色碰撞区，决定"哪儿不能走"。碰撞类型有 Solid（实体阻挡）、单向的 Top/Bottom/Left/Right（只挡某一侧，做平台和半固体很常用）、平台类专用的 Ladder（爬梯）。
- **演员与触发器**：场景里的人和互动点。

场景有 5 种内置类型，决定玩家控制手感：

| 场景类型 | 手感 | 例子 |
|----------|------|------|
| **Top Down** | 四方向移动，RPG 式 | 宝可梦、塞尔达(早期) |
| **Platformer** | 重力+跳跃，左右移动 | 马里奥、超级喵 |
| **Adventure** | Top Down + 支持斜向、环绕角落 | 织梦岛式冒险 |
| **Shoot'em Up** | 飞船式水平/垂直滚动射击 | 沙罗曼蛇 |
| **Point and Click** | 鼠标式点击互动 | 猴岛小英雄 |

### 2.2 演员（Actor）

演员是场景里的角色和物体：玩家、NPC、门、宝箱、敌人……每个演员可以绑定一张**精灵图（Sprite）**，并挂 4 种脚本：

- **On Init**：场景加载时执行一次（放音乐、初始化变量）。
- **On Interact**：玩家面向它按下 A 键时执行（对话、开门、捡东西）。
- **On Update**：每帧循环执行（巡逻 AI、动画）。
- **On Hit**：发生碰撞时执行（战斗伤害、踩怪）。

演员还能设**碰撞组（Collision Group）**，配合 On Hit 做"碰到就生效"的逻辑。

### 2.3 触发器（Trigger）

触发器是一个矩形区域，玩家**走进（On Enter）**或**走出（On Leave）**时触发脚本。场景切换几乎全靠它：站在房门那俩格子进触发器 → 切换场景。

### 2.4 事件（Event）

事件就是"剧本语句"，是 GB Studio 的核心。常见的有：

| 事件 | 作用 |
|------|------|
| **Show Text** | 弹对话气泡，可换行、可放头像 |
| **Change Scene** | 切换场景并指定出生点 |
| **Set Variable / If True** | 操作布尔变量，实现分支逻辑 |
| **Actor Move To/Relative** | 让演员移动（动画、动画完成回调） |
| **Play Music / Play Sound** | 放 BGM 或音效 |
| **If Actor At Position** | 判断演员到没到某处 |
| **Deactivate** | 隐藏/禁用演员或触发器（捡完的东西就消失） |

变量是 `$名称` 形式，最常用的是布尔值（`true/false`），做"有没有钥匙""任务完没完成"这类状态。

## 三、安装与第一个项目

### 3.1 获取

1. 打开 [gbstudio.dev](https://www.gbstudio.dev)，点 Download → 跳转到作者的 itch.io 页面 → 下载对应平台（Windows / macOS / Linux）安装包。
2. 源码在 [github.com/chrismaltby/gb-studio](https://github.com/chrismaltby/gb-studio)，官方文档在 [gbstudio.dev/docs](https://www.gbstudio.dev/docs)。

### 3.2 新建项目

启动后会看到启动页：可以打开最近项目、新建空项目，或者打开 **示例项目（Sample Project）**。强烈建议先打开示例项目逛一圈——它把所有场景类型、触发切换、存档、敌人巡逻、对话都做了一遍，等于把教程演给你看。

新建空项目时选期望的默认场景类型即可，之后的场景各有各的类型，随时可加。

### 3.3 界面布局

- 左侧是项目结构树：场景、精灵、背景、音乐、字体、变量。
- 中间是 **Game World** 视图，能看到所有场景和它们之间的连接箭头。
- 右侧/底部是属性面板和脚本编辑面板。

改任何东西随时按播放键（或 `F5`）测试，编译只要几秒——这个反馈速度比很多现代引擎还快。

## 四、完整示例：做一个"找钥匙开门"的迷你游戏

下面我们把上面所有概念串起来，做一个极简 Top Down 游戏：一个房间、一扇门、一把钥匙、一句提示。目标是熟悉**场景→演员→触发器→事件→变量**整个链路。

### 4.1 画背景

1. 在项目树里 Backgrounds 点 `+`，用内置像素工具画一个房间：中间空地（草地/地板），四周围一圈墙。墙壁画成深色块，地板画成浅色。
2. 把背景拖到场景的背景槽里。

### 4.2 刷碰撞

选中场景，切换到 **Collision 工具**，把墙那一圈刷成红色（Solid）。地板留空——玩家就能在房里自由走、但翻不过墙。这一步直接决定了"哪里能走"。

```
┌─────────────────────────┐
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │   ▓▓ = Solid 碰撞（红）
│ ▓▓                    ▓▓ │
│ ▓▓   🗝️   🧍 →  🚪   ▓▓ │   🗝️ 钥匙演员
│ ▓▓                    ▓▓ │   🚪 门演员
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │
└─────────────────────────┘
```

### 4.3 放演员

- **玩家**：默认就有，场景类型带玩家精灵。
- **钥匙**：从精灵库里做个 8×8 的小钥匙精灵，放到场景里作为一个 Actor。
- **门**：用两帧动画做个"门"精灵放在出口。给门的演员写脚本：

```
Actor: 门 (Door)
  On Interact:
    如果 $hasKey == true
        → Show Text "门开了，你逃出去了！"
        → Deactivate（门消失）
    否则
        → Show Text "门上锁了，需要一把钥匙。"
```

- **钥匙**演员的脚本：

```
Actor: 钥匙 (Key)
  On Interact:
    → Show Text "拿到了钥匙！"
    → Set Variable $hasKey = true
    → Deactivate（钥匙从场景里消失）
```

### 4.4 用触发器做通关出口

在房间另一侧放一个 Trigger（画个矩形），`On Enter` 里接：

```
On Enter:
  → Show Text "恭喜通关！"
  → Change Scene → 结束画面场景
```

### 4.5 测试与构建

按播放键（Play）测试：先碰钥匙拿到 `$hasKey=true`，再去碰门——门开了；没钥匙时碰门——被拒绝。整个"条件判断"由变量驱动，理解的正是事件的威力。

构建导出：

- **Export → ROM**：生成 `.gb`（黑白机）或 `.gbc`（彩色），模拟器直接能跑。
- **Export → Web**：生成网页版，扔 itch.io 就能在线玩。
- 有 EverDrive GB / GBxCart 之类的烧录器，把 `.gb` 写进闪存卡，插真机体验原汁原味。

## 五、再进一步：让逻辑复杂起来

入门后可以玩的东西越来越多，这里列几条从官方文档沿袭的进阶路径：

1. **平台游戏**：Platformer 场景内置重力、跳跃、爬梯、单向平台；4.x 版本还整合了冲刺、二段跳、墙体反弹、Coyote Time（土狼时间，离开平台边缘后短暂的起跳缓冲）等特性，全部可开关。
2. **敌人 AI**：演员 `On Update` 里用 `Actor Move To` + 位置判断做来回巡逻，配合碰撞组实现踩怪伤害。
3. **数据表**：`Data Table Lookup` 事件支持从 CSV 读静态数据（怪物属性、道具表），做一个 RPG 级的清单管理。
4. **音乐**：内置音乐编辑器（钢琴卷帘 / Tracker 两视图），支持 MIDI 输入，也支持 hUGETracker 的 `.uge` / `.mod` 格式——作曲也有配套工具（music.gbstudio.dev）。
5. **插件**：GB Studio 支持引擎插件、事件插件、主题/本地化插件，还能做"引擎 Eject"后直接改生成的 C 代码——硬核玩家就这样无缝过渡到 GBDK 手写 C。

## 六、工程化视角的几句结语

作为工程师，抛开"做游戏好不好玩"这件事，GB Studio 有几个点很值得学习：

- **限制驱动的设计**：硬件约束（内存、精灵数、色板）直接变成设计决策，这和嵌入式开发里"资源优先"的思维完全同源。
- **可视化 + 可追溯**：事件链本质是序列图，每个分支都能看到触发源，比翻一堆 `if/else` 更容易给人讲清楚。
- **"编译错误"极低**：因为是结构化构造 + 自动代码生成，犯低级语法错的概率基本为零，可以专心在玩法上。

如果你此前写过 FPGA、裸机或嵌入式，一定会对这种"约束下造物"的快乐产生共鸣。而如果你只是想试试游戏开发，那再没有比 GB Studio 更平缓的坡道了——点开示例项目，Play，然后开始改。

Happy hacking on the DMG!
