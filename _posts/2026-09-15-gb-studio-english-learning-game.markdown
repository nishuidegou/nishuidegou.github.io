上一篇介绍了 GB Studio 的入门原理。这篇顺着它的能力边界做一个实际问题：**能不能用它给孩子做一套学英语的互动游戏？** 答案是能，而且"单词卡 + 闯关 + 评分"这类玩法几乎是 GB Studio 的舒适区。本文以《新概念英语》青少版某一课的两个词汇为例，从玩法设计、文字与发音限制，到完整的事件链设计，讲清楚怎么落地。

## 一、为什么这种游戏适合 GB Studio

儿童学习类游戏的核心交互只有三四种，恰好全是 GB Studio 的原生能力：

| 交互 | GB Studio 实现 |
|------|----------------|
| 选择题/选项 | `Menu` 事件出选项，配合变量分支判对错 |
| 看词选图 / 看图选词 | Point and Click 场景，点触发器（Trigger）判定 |
| 拼写填空 | 用"字母盘"（一组可交互演员或 `Menu`）逐字选择 |
| 进度与奖励 | `Set Variable` 累计分数和关卡数，星/金币作为收集品 |

没有复杂的物理、没有大世界，逻辑全在"点谁 → 判对错 → 给反馈 → 进下一题"，这正是事件脚本擅长的流水线。

## 二、想清楚的两个硬约束

### 2.1 文字：英文好办，中文要克制

Game Boy 的 tile（8×8 像素块）存字，一片屏也就显示约 20 个字符宽。所以：

- **英文单词和数字**：默认字体直接支持 ASCII，零成本，放心写。
- **中文释义**：每个汉字占一个 tile，只能自绘一张"只含用到的字"的字体 PNG，再用 4.x 的 `Set Font` 事件切字体。**别想着塞整段中文句子**——要么用图标代替，要么把中文压缩到单个字（如"猫""狗""苹果"）。
- 推荐的展示方式：**大图 + 英文单词**，中文只出现在答案反馈一行里。

### 2.2 发音：别指望"真人朗读"

Game Boy 的音源是 4 声道（方波×2、波形、噪声）。真人单词发音只能切片成 4-bit 采样走波形声道，效果是 8kHz 电话音质，听长句基本靠猜。建议：

- **短单词采样**做"听音选词"（只能塞一课里最常用的 10 个内）。
- 或者放弃真人发音，改用**音效反馈**：选对一声短音、选错一声"咚"，配合自谱的儿歌风 BGM——对低龄儿童来说，反馈感主要来自音效和动画，发音可以靠家长真人带读。

## 三、玩法设计：一课一关的「看图选词」

以下是用《新概念英语》青少版“Hello, Peter!”一课中 `boy` / `girl` / `cat` / `dog` 四个词设计的关卡。

### 3.1 场景结构

```
Scene: 关卡1（Point and Click）
  ├─ 背景：一张 160×144 像素图，中间画 4 个空白格
  ├─ 4 个"答案格"演员：显示选项单词（boy / girl / cat / dog）
  ├─ 1 个"出题板"演员：显示当前要选词的英文提示（或画一个图案）
  └─ 若干 static 说明文字（"Points: $score / Lives: $lives"）
```

### 3.2 全局变量

| 变量 | 作用 | 初始 |
|------|------|------|
| `$score` | 答对得分 | 0 |
| `$lives` | 生命数，3 次答错则游戏结束 | 3 |
| `$q` | 当前题号（代表出哪个题） | 0 |
| `$ansOK` | 本答对标记（防止连点刷分） | false |

### 3.3 出题逻辑（场景 On Init）

用 `Switch` 事件按 `$q` 出题——出题板换成对应图案、把 `$ansOK` 复位：

```
Scene: On Init
  → Play Music（欢快的 BGM）
  → Switch: $q
      0: 出题板显示 "cat" 图案；$ansOK = false
      1: 出题板显示 "dog" 图案；$ansOK = false
      2: 出题板显示 "boy" 图案；$ansOK = false
      3: 出题板显示 "girl" 图案；$ansOK = false
      4: → Change Scene → 结束/结算场景
```

### 3.4 点击判定（每个选项演员 On Interact）

以"cat 选项"为例：

```
Actor: 选项"cat"
  On Interact:
    如果 $ansOK == true → 什么都不做（防止连点）
    如果 $q == 0    （本题正确答案就是 cat）
        → Show Text "对啦！cat，喵～"
        → $score = $score + 1  用「Set Variable Add」
        → Play Sound（对音效）
        → $q = $q + 1；$ansOK = true
        → Wait 1s → 重新出下一题（用事件"Rerun/返回场景开头"或换成下一题图案）
    否则
        → $lives = $lives - 1
        → Play Sound（错音效）
        如果 $lives <= 0 → Show Text "再多练练哦！" → Change Scene 结算
        否则 → Show Text "再想想，它不叫这个哦"（不改变题号，换换试）
```

另外三个选项演员逻辑相同，只是"正确答案行"改成自己对应的 `$q`。

### 3.5 结算场景

结尾用 `If` 判断分数给三档评语，并回到关卡可重玩：

```
Scene: 结算
  On Init:
    如果 $score >= 4 → Show Text "太棒了！满分！" → 播放胜利音效
    否则，如果 $score >= 2 → Show Text "不错！再练一次吧！"
    否则 → Show Text "别灰心，再来一次！"
  → Menu: "再玩一次 / 返回首页" → 对应 Change Scene
```

## 四、把事件做成一课一关的"模板"

尝到甜头后，不必每个词都重新摆场景。工程化的做法：

1. **词库驱动**：把 `cat/dog/boy/girl` 等做成"图案精灵 + 单词精灵"，同一套场景复用，只换 `$q` 对应的图案。
2. **数据表**：4.x 的 `Data Table Lookup` 事件可以直接读 CSV（单词、图案索引、读音采样索引），加词不改逻辑。
3. **分课分关**：每课一个场景文件（Lesson1 / Lesson2…），用触发器或菜单进入；评分变量各关独立，通关解锁下一关（用 `$unlock` 布尔变量）。

这种"一变数据、多关同构"的思路，跟嵌入式里"表驱动"的思维一模一样：逻辑一份，数据多份。

## 五、导出与真机体验

- **试玩**：`Export → Web` 后直接给孩子在平板上点；Point and Click 场景本身就是为指针设备设计的，体验最好。
- **ROM**：导出 `.gb` 到模拟器（推荐 Emulicious/BGB），或烧进 EverDrive 真机——能让孩子自己捧着掌机背单词，仪式感拉满。
- **中文补充**：如果坚持要中文提示，记得用自绘字体 PNG 并**只含用到的十几个字**，否则 ROM 体积和 tile 占用会吃紧。

## 结语

给孩子做学习游戏，难点从来不在技术，而在"反馈是否及时、失败是否可重来"。GB Studio 恰好把这两件事做得很轻：对错立刻有声有形、生命值可循环、关卡可反复刷。一次做成"cat 看图选词"，就能快速复制成几十课的单词闯关——这大概也是 8-bit 掌机给孩子学英语最好的打开方式。至于真人发音，等孩子学会自然拼读，再让 Wave 声道录个短词吧。
